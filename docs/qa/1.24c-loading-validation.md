# 1.24c — Long-career loading optimization validation

## Change
In `game/runtime-096g.js`, `applyCareerPlayerState()` already builds a fresh player-ID Map. It formerly called `FD.getPlayer(id)` on every missing saved player ID. That method can fall back to full-roster scans. The candidate now consults the existing Map for both the original key and its eight-hop canonical alias. The original ID has precedence to preserve restoration behavior.

The 1.24b youth-save lookup improvement remains included.
