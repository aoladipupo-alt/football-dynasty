# 1.24f — Continental fixture simulation performance and regressions

## Code change

The real `FDContinental.advance()` previously simulated each eligible fixture by
calling `simulateFixture()`, which scanned `FD.allPlayers` **twice per match**
(home and away). The 1.24f candidate builds one transient `Map<clubId,players[]>`
when the first AI fixture is due and caches the eligible top 11 per club for the
current advance call. The scorer/assister RNG and competition progression remain
unchanged.

Safety boundaries: the index is **not stored in save data**; no index is built if
there is no fixture due; a new advance rebuilds the index to reflect loans,
transfers, academy promotions and player development. The original direct
four-argument `simulateFixture` API still works unmodified.

This cumulative 1.24f build also contains the 1.24b youth-save, 1.24c old-save
restore, 1.24d training and 1.24e AI lineup optimizations.

## Remaining release gate

These are controlled operation-count tests, not measured end-to-end
matchday speedups on a Chromebook. The complete browser UI, manual match
interaction, career save/reload, calendar continuation, deadline hour handling
and 10-season gameplay have **not** passed a live browser smoke test in this
session. Previous browser navigation was blocked in this environment.

The development branch is intentionally not deployed. Keep the existing
GitHub Pages site and user career saves unchanged until a real browser test
passes.
