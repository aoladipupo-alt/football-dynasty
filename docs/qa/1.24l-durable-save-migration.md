# Football Dynasty 1.24l: verified legacy migration (development only)

**Release status: BLOCKED.** This increment adds verified migration paths to the 1.24k atomic IndexedDB checkpoint vault. It does not yet make IndexedDB authoritative for live simulation writes. Never publish to Pages until issue #1 acceptance criteria pass.

## Architecture

The existing football-dynasty-career-vault-124k database and checkpoint format remain backward compatible. Each slot maintains an atomic head/previous pair with SHA-256 verification and compare-and-swap revision protection. API version 2 adds:

- migrateLegacy(slot, storage, validator): capture the ten original raw JSON save fields, check occupied slot and parseability, inspect 1.24j LZW player archives and shadow academy sidecars, reject racing modifications, transactionally commit and verify the SHA, then optionally call the game's portable backup validator. Original localStorage fields are never modified. A repeat migration of identical bytes is idempotent.
- importPortable(slot, backup, validator): accept the existing nine-field portable career format, map embedded academy data back into the sidecar, atomically commit to IndexedDB, and confirm a valid roundtrip through exportPortable. Previous verified checkpoint is retained.
- storageReport(): compare legacy localStorage character counts, IndexedDB slot sizes, browser storage usage/quota.
- Explicit failure for unavailable IndexedDB, transaction abort, quota error and corrupted current head; never treat a queued or aborted write as persisted.

Settings' existing **Protect career (IndexedDB)** action now runs the verified, non-destructive migration.

## Browser test coverage

tests/career-migration-124l.test.cjs is included in the new non-deploying GitHub Actions Chromium suite. It starts the real game on a 1366 x 768 viewport, then tests raw saves, compressed player archives, foreign academy sidecars, idempotent migrations, preserved originals, portable export/import equivalence, two independent slots, ten *synthetic storage-only* season revisions with growing fixtures/transfers/youth, reload invariants, interrupted transactions, injected QuotaExceededError, denied IndexedDB, and storage/heap/load measurements.

The existing 1.24k checkpoint test and 1.24j two-career 41-day real-match test also run unchanged.

## Remaining blockers for issue #1

1. Live engine still reads and writes active careers synchronously through localStorage. IndexedDB does not yet solve the current quota failure. Implement a startup hydration/cache path and awaited durable commit barrier before removing legacy large values. Original bytes must remain until the complete cutover is verified.
2. Update actual game import, previous-import recovery, delete and slot switch flows to honor authoritative IndexedDB writes and never report success before transaction completion.
3. Run actual 10- and 20-season simulations (not only synthetic vault revisions), with two occupied slots, match scores, transfers, youth identities, reload/recovery and full invariant comparisons.
4. Benchmark cold/warm loads and memory on Chromebook-class hardware at new, 5-, 10- and 20-season checkpoints. A Chromium Ubuntu runner at Chromebook resolution is not equivalent to Chromebook hardware.

The published site, main branch and users' existing local careers have not been modified. No workflow in this branch deploys to Pages.
