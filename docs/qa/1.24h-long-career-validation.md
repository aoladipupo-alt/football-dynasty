# Football Dynasty 1.24h — Long-career restore and save-footprint validation

## Change

A long career retains historical transfers for players who may have subsequently
retired, left the active roster, or been consolidated under a canonical player
ID. During load, `applyCareerTransferHistory()` already builds a fresh
`Map<playerId,player>`, but previously called `FD.getPlayer()` on
missing IDs. Each unmatched ID could then scan the entire roster twice.
The 1.24h candidate reuses that map with the established eight-hop legacy
alias resolver.

The change does not truncate history, delete player records, alter transfer
replay order, change the save schema, or persist an extra cache.

A separate **opt-in read-only** browser diagnostic is available in
`diagnostics/career-footprint-124h.js`. When pasted into a test career's
DevTools and invoked with `FDStorageFootprint124h.report()`, it prints
approximate UTF-16 save sizes for each of five save slots and storage
categories. It never logs save contents or writes storage. These estimates
are not actual disk-quota measurements.
