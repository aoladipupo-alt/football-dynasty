# 1.24j — Real-browser calendar, two-career isolation, and quota-safe player snapshots

**Status:** Development candidate; automated browser and package tests pass; longer-term localStorage ceiling remains a release blocker.

## Change

Large full-career player-state snapshots are now stored using the existing
versioned UTF-8 LZW codec when compression substantially reduces their size.
The on-disk marker is `fd-player-career-lzw-124j`. Reads transparently restore
the exact player-state object, while uncompressed older careers continue to
load normally. Career exports and previous-import recovery backups decode the
snapshot so downloaded JSON retains the original portable backup schema.

The previous 1.24b–1.24i optimizations are preserved. Main branch and
existing user career files were not changed.

## Remaining risk — NOT ready for long-career release

In the earlier *uncompressed* two-career Chrome scenario, `localStorage`
held approximately **5,240,534 characters** and the first match result failed
to persist. The largest key was a 2,563,958-character player-state snapshot.

The compressed 1.24j scenario persisted correctly, but still held
approximately **4,833,873 characters** across storage keys after just the first
competitive match, including a **1,520,947-character compressed player-state
key**. This is close to the browser's practical localStorage limit; quota
behavior varies by browser. A 10-season career has NOT been verified and the
game is still vulnerable to long-term growth across multiple slots. Do not
assume this specific regression fix establishes multi-year save durability.

**Required follow-on:** Move large versioned career payloads to an atomic
IndexedDB-backed store with safe migrations, two-slot recovery, rollback and
export compatibility, or another tested durable storage design. Avoid deleting
history as a workaround. Benchmark actual storage usage and Chromebook
performance at new, 5-, 10- and 20-season careers.

This is a test candidate on `work/1.24b-career-performance`; do not deploy
the live GitHub Pages release until the long-career storage gate is addressed.
