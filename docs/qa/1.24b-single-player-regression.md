# 1.24b Single-player regression gate

Status: test specification only; no engine changes or test passes implied.
Published baseline: README describes 1.23f package (1.23b engine / 1.23d launcher). Confirm actual build version before changing release.

## Test matrix
For each career age (new, 1, 5, 10, 15 seasons), use a disposable test save:
1. Load career and capture club, season, calendar date, money, squad IDs, academy IDs, standings and transfer history.
2. Advance one day, one week, one month, through a transfer-window boundary, and through a season rollover.
3. Save, reload, and compare captured invariants plus expected progression.
4. Export and import into a clean browser profile. Verify identities and totals are unchanged.
5. Simulate an interrupted write; verify the last valid save can still be loaded.
6. Repeatedly open and close the same career. Check listeners and timers are not duplicated.

## Academy invariants
- Annual intake occurs exactly once per club per season, including after reload mid-rollover.
- Confirm intended 10 players per club per year, without duplicate player IDs.
- Academy graduates at the intended 74+ threshold; no player exists simultaneously in academy and first-team lists.
- Loaned players have one owning club and at most one active loan destination.
- Aging and development happen once per season tick, not again on reload.

## Performance measurements
Capture browser/device, build commit, career size, season, and 10 repeated samples for each:
- Cold load and warm load: time to playable career.
- Day/week/month advance: median, p95, worst.
- Season rollover: elapsed time and peak memory where supported.
Compare against the prior released build on the same device; do not report speedups without measurements.

## Release blockers
- Any data loss or corrupt save; duplicated players or season processing; negative/invalid club finance values caused by simulation; failed browser smoke test; broken asset links.
- Failed archive checksum, missing packaged assets, or runtime console errors on a fresh career.

## Workflow
Implement one focused change in a separate branch -> run relevant regression checks -> inspect failures -> repeat. Keep the published site unchanged until a real browser playtest and save round-trip pass.
