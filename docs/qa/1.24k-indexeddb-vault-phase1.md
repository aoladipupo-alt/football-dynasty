# Football Dynasty 1.24k — Atomic IndexedDB checkpoint vault (phase 1)

**Status:** Non-destructive development candidate. Real Chromium and cumulative engine tests passed. **The main game still uses localStorage as its live save system; this is not the full durable-save migration.**

## Shipped on development branch

- New `game/durable-career-vault-124k.js` implements a separate IndexedDB database with an atomic `head` and `previous` revision for each of five save slots.
- Checkpoints copy the original raw JSON save fields into IndexedDB; they do not remove, overwrite, or migrate localStorage careers.
- Each revision includes SHA-256 verification of all canonicalized save fields, format marker, slot, revision and timestamp.
- A new checkpoint writes the previously verified head and new head in **one IndexedDB readwrite transaction**. Simultaneous updates are rejected by revision/hash compare-and-swap instead of silently overwriting a later checkpoint.
- Reading a corrupted current checkpoint falls back to the verified prior one. The vault refuses to write on top of an invalid head, preserving forensic recovery.
- Settings offers **Protect career (IndexedDB)** and **Download protected checkpoint**. The latter converts the 1.24j compressed player snapshot and foreign-academy sidecar into ordinary, game-validated portable backup JSON.
- Confirmed **Delete career** deletes its own protected checkpoints without affecting another slot. Confirmed **Delete all careers** deletes all vault and local career data. Deletion waits for the IndexedDB transaction before continuing.
- The existing single-player runtime, compression, match center, and previous 1.24b–1.24j optimization changes remain intact.
- No background/cloud synchronization and no automatic protected backup. A checkpoint is created only when the user explicitly clicks Protect career.

## Critical limitations and 1.24k phase 2

This checkpoint feature is **not yet automatic** and **does not reduce the size of the game's ongoing localStorage saves**. Existing game simulation still writes the 1.24j compacted player-state payload plus world, transfer and match data to localStorage. The live multi-year quota problem tracked in [issue #1](https://github.com/aoladipupo-alt/football-dynasty/issues/1) remains open.

Next implementation steps: make IndexedDB the authoritative live store for the large save records without pretending queued asynchronous writes are durable; use atomic per-day or per-checkpoint transactions and explicit commit barriers; migrate existing raw, 1.24j-compressed and shadow-sidecar payloads transactionally; preserve portable backups, deletes and rollback; verify simulated crashes, quota refusal, multi-tab conflicts and 10+ season saves in real Chromium/Chromebook browser tests.

Do not promote or publish the 1.24k candidate as the default game until that live storage migration is validated. Published GitHub Pages and actual user career saves remain unchanged.
